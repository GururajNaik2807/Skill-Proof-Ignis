Executive Summary & Problem Statement1.1 Executive SummarySkillProof is a developer career verification SaaS that audits technical skills claimed on an engineer’s resume against concrete, verifiable evidence from their public GitHub repositories. Rather than relying on static resume bullet points or superficial AI buzzwords, SkillProof parses codebase artifacts (languages, dependencies, commit recency, unit tests, and DevOps configs) to categorize skills into Proven, Partial, or Claimed-Only tiers. Candidates can then match their verified profile against any target Job Description (JD) to spot true skill gaps and receive actionable 1–2 hour micro-tasks to close them.1.2 The ProblemResume Inflation & Buzzword Saturation: Applicants list frameworks and languages after watching brief video tutorials, making resumes unreliable for recruiters.Lack of Trust in AI Summaries: Recruiters and engineers distrust automated stamps that declare a candidate "verified" without showing where the code lives.Action Paralysis for Job Seekers: Candidates rejected from roles are given no actionable feedback on how to turn an unproven resume claim into real code proof.1.3 The SolutionSkillProof establishes an evidence loop:$$\text{Claim} \longrightarrow \text{GitHub Code Inspection} \longrightarrow \text{Evidence Audit} \longrightarrow \text{JD Gap Analysis} \longrightarrow \text{Micro-Task Generation} \longrightarrow \text{New Evidence}$$2. Core Value Proposition & Evidence ModelSkillProof enforces an uncompromising rule: A skill is never marked "verified" purely by an LLM prompt response. Every verification tier must be grounded in physical codebase signals.2.1 Verification Tiers & Deterministic SignalsTierStatus ColorDefinitionRequired Signals (Heuristics)Proven#2E8B6F (Emerald)Deep, functional codebase presence with proof of maintenance and testing.All or most of:• Primary/secondary language bytes in non-fork repos• Declared in package manifests (package.json, pyproject.toml, go.mod, etc.)• Recent commit activity (< 12 months)• Automated test files detected (tests/, *.spec.ts, *_test.py)• Multi-file codebase footprintPartial#C58A24 (Amber)Surface-level or dated presence; missing testing or active maintenance.At least one of:• Present only in configuration or boilerplate templates• Inactive repositories (> 12–18 months without commits)• Zero unit test suites or integration runners• Forked repository with minimal candidate commitsClaimed-Only#8A6255 (Muted Rust)Stated on resume, but completely absent from public code.• Skill parsed from uploaded resume PDF• Zero matching repositories, manifests, files, or commits found on GitHub3. User Personas & User Journeys3.1 Primary PersonasThe Early-Career Developer (Alex): Wants to prove their real ability without 5 years of formal industry experience. Alex needs to know which skills on their resume look unconvincing and needs concrete micro-tasks to build credible proof.The Technical Recruiter / Hiring Lead: Wants an authentic 1-page evidence breakdown with deep-links to files and commit histories to bypass resume fluff during initial screenings.3.2 Primary User JourneyOnboarding: User signs up $\rightarrow$ Enters target role $\rightarrow$ Validates GitHub handle $\rightarrow$ Uploads resume PDF.Analysis Trigger: Background processes scan public repos, parse resume text with Gemini, and cross-reference evidence.Evidence Matrix Review: User views their dashboard breakdown: Proven vs. Partial vs. Claimed skills with clickable source links.Target Job Match: User pastes a job posting. SkillProof extracts required technologies and creates an alignment score.Skill Gap Micro-Tasks: SkillProof flags missing/unproven requirements and creates actionable coding tasks (e.g., "Add PyTest suite with 80% coverage to api-gateway").4. Classification Engine (Stage 5)FR-EVI-1: Run deterministic heuristic rules matching resume_skills against github_repositories.FR-EVI-2: Assign one status: proven, partial, or claimed.FR-EVI-3: Attach
